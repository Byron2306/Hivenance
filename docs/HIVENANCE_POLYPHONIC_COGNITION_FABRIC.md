# HiveNance Polyphonic Cognition Fabric

**Status:** canonical architecture specification  
**Scope:** Phoenix relative-value research organism  
**Authority:** research only; no live execution or promotion authority

## 1. Purpose

HiveNance is not a voting swarm of indicators.

It is a distributed market-research cognition fabric in which independent evidence families observe the same bound world state, communicate hypotheses, recruit or challenge one another, propagate urgent changes, form multi-timescale resonance, face adversarial falsification, account for cognitive expenditure, and produce governed research conclusions.

Phoenix is the first market-research organism running on this fabric.

## 2. Constitutional separation

The architecture preserves six hard separations:

1. **Observation is not interpretation.**
2. **Correlation is not causation.**
3. **Resonance is not truth.**
4. **Confidence is not authority.**
5. **Research support is not execution permission.**
6. **Synthetic evidence is not prospective market proof.**

## 4. VNS — Verified Market Nervous System

Metatron uses VNS as an independent network-truth layer.

Phoenix adapts the pattern into a market sensory boundary.

VNS is allowed to record observations such as:

- public venue timestamps;
- bid / ask / midpoint;
- spread;
- order-book depth;
- public trade flow;
- route availability;
- data quality and freshness;
- public Horizon context;
- source lineage and digests.

VNS must not infer a trade direction.

Every downstream receipt must be traceable to VNS evidence.

## 7. Waggle Protocol

The Waggle Protocol is the colony's typed hypothesis language.

Canonical messages:

- `WAGGLE` — bounded hypothesis proposal;
- `FOLLOW` — independent corroboration;
- `DISSENT` — independent contradiction;
- `SEARCH` — request targeted evidence;
- `ABANDON` — withdraw prior support;
- `ALARM` — prerequisite or relationship failure;
- `SETTLE` — future outcome is now observable.

A Waggle receipt should bind:

- world_state_id;
- pair / asset / market scope;
- horizon;
- hypothesis class;
- direction or abstain;
- expected magnitude if available;
- uncertainty;
- evidence family;
- lineage digest;
- evidence root;
- authority.

## 9. Market Hunting

Metatron's threat-hunting engine proactively searches telemetry for defined patterns.

Phoenix adapts this into proactive market hypothesis hunting.

A hunt is not a forecast and not an action. It is a bounded question such as:

- extreme relative displacement + flow exhaustion;
- depth depletion followed by recovery;
- relative spread excursion while relationship stability remains high;
- structural-break candidate;
- cross-pair asset shock;
- forecast-family disagreement spike;
- low-cost direct-route anomaly;
- context-burn anomaly;
- pulse cascade without independent evidence.

Each hunt must declare:

- required data sources;
- deterministic detection logic;
- falsification condition;
- scope;
- severity / research priority;
- false-positive notes;
- output message type, normally SEARCH or ALARM.

## 10. Colony Correlation

Metatron's correlation layer enriches and links evidence across observations.

Phoenix colony correlation links events across:

- time;
- pair;
- shared asset;
- venue;
- feature family;
- hypothesis family;
- cascade ancestry.

Correlation output must preserve:

- correlation score;
- contributing observations;
- shared entities;
- temporal distance;
- family diversity;
- confidence;
- explicit `causal_claim=false` unless a separate causal analysis supports one.

Correlation can promote attention, not authority.

## 11. Causal Cascade

Correlation asks whether observations are related.

Cascade asks whether an evidence-supported propagation path exists.

Example:

```text
aggressor sell burst
→ book depletion
→ relative spread excursion
→ quote OFI turn
→ depth recovery
→ reversal forecast
```

Cascade scope may expand:

```text
PAIR → CONNECTED PAIRS → ASSET → MARKET
```

Every edge must carry evidence and timing.

## 12. Hive Pulse

Hive Pulse is the fast nervous impulse of the colony.

Canonical pulse classes:

- SEARCH_PULSE;
- DISCOVERY_PULSE;
- ALARM_PULSE;
- FREEZE_PULSE;
- CLEAR_PULSE.

A pulse carries:

- scope;
- severity;
- confidence;
- world_state_id;
- lineage;
- evidence root;
- TTL;
- decay;
- corroboration count;
- independent-family count;
- cascade depth.

Uncorroborated pulses decay.

Independent corroboration can increase research attention.

Positive pulses must never increase execution authority.

Negative pulses may reduce or freeze authority immediately.

## 15. Mystique counterfactual maze

Metatron Mystique builds coherent mirror worlds to exhaust adversarial reasoning.

Phoenix uses explicitly synthetic counterfactual worlds to attack its own hypotheses.

Examples:

- remove the largest trade;
- remove depth recovery;
- invert flow;
- double spread cost;
- break relationship stability;
- remove one evidence lineage;
- change Horizon regime;
- perturb timing within measured uncertainty.

Mystique output is a falsification receipt:

- worlds tested;
- worlds survived;
- failure modes;
- evidence dependencies;
- fragility score.

Synthetic worlds are never mixed with prospective market evidence.

## 16. Cognitive metabolism

Adapted from Metatron CBR / TBCR / CDI.

Phoenix measures:

### Research Context Burn Rate

Evidence or observation budget consumed per new useful settled information unit.

### Tool Budget Consumption Rate

Model / tool evaluations per useful settlement.

### Confidence Degradation Index

Relative decline between hypothesis confidence at formation and confidence after settlement.

The metabolism layer controls research attention.

It cannot grant execution authority.

High burn with low information gain should lead toward ABANDON.

## 17. Learned Challenger / ML

Metatron contains network anomaly, classification, time-series and ensemble ML.

Phoenix ML is a challenger family, not an oracle.

Permitted roles:

- anomaly detection;
- event classification;
- probability-of-threshold-crossing models;
- flow-exhaustion classification;
- regime classification;
- learned forecast challenger;
- calibrated ensemble challenger.

Requirements:

- time-ordered training;
- outcome-lag protection;
- explicit train / validation provenance;
- baseline comparison;
- calibration;
- leave-one-pair / leave-one-asset diagnostics;
- dependence-aware uncertainty;
- versioned model lineage;
- no same-window tuning presented as validation.

Synthetic training may test software behavior only.

It cannot establish edge or promotion evidence.

## 20. Edge Chorus

Edge Chorus governs the integrity of a specific research transition.

It is not a forecast choir and not a substitute for Polyphonic Resonance.

Adapted from Metatron's `ChorusEngine`, Phoenix Edge Chorus verifies that a bounded research edge contains the right companions, sequence, timing, closure and settlement evidence.

A Phoenix research edge may define:

- required participants;
- optional participants;
- expected sequence;
- timing tolerances;
- required state events;
- required audit events;
- required companions;
- settlement timeout.

Example research edge:

```text
prospective_hypothesis_settlement

required participants:
  world_state_bind
  triune_verdict
  outbound_gate
  settlement_engine
  nurse
  audit_closure

expected sequence:
  edge_opened
  world_state_bound
  triune_resolved
  research_release
  settlement_started
  settlement_completed
  nurse_recorded
  audit_closed
  edge_settled
```

Edge Chorus scores:

- companion presence;
- sequence resolution;
- mesh entrainment / timing;
- audit closure;
- settlement completeness.

Resolution classes:

- CONSONANT;
- STRAINED;
- DISSONANT;
- FRACTURED.

A fractured or materially dissonant research edge cannot be treated as settled evidence.

Edge Chorus therefore answers:

> Did this research transition occur correctly?

It does not answer:

> Was the market hypothesis true?

## 21. Notation Tokens

Notation Tokens are narrow, world-state-bound permissions to perform one specific governed research transition.

They are adapted from Metatron's notation-token lifecycle while preserving Phoenix's research-only authority.

A Phoenix Research Notation Token should bind at minimum:

- token_id;
- governance_epoch_id;
- score / programme id;
- voice role;
- capability class;
- world_state_id / world_state_hash;
- issued_to;
- entry window;
- sequence slot;
- required companions;
- response class;
- action digest;
- target digest;
- authority-request digest;
- consequence class;
- audience;
- maximum uses;
- issued_at;
- expires_at;
- status;
- signature / receipt reference.

Default behaviour should be:

- short-lived;
- single use;
- invalid after material world-state drift;
- invalid outside its entry window;
- invalid for a different target or research transition;
- invalid if required companions are absent;
- invalid if revoked by pulse, harmonic, Triune, or authority state.

Notation does not create new authority.

It narrows already-granted research authority into a concrete, bounded transition.

Examples:

```text
ALLOW:
  settle forecast F against horizon H
  open prospective observation window W
  publish research receipt R
  invoke Mystique challenge M
  run approved challenger model C

NOT ALLOW:
  submit real order
  change Phase 6/7 authority
  promote model from same-window evidence
```

## 22. Governance epoch and score

Notation is most useful when issued inside a frozen research governance epoch.

A governance epoch binds:

- active experiment definition;
- world-state hash;
- model / lineage registry;
- harmonic thresholds;
- hunt rules;
- pulse rules;
- cost model;
- settlement schema;
- authority boundary.

The score defines the expected research sequence.

The token is therefore not merely permission.

It is permission to play one specific note in one specific score, inside one specific world state.
